# 阶段产出与验收

完整范围保留。此前 6/8/10 周与小时分配是未经验证的估计，不作交付承诺。阶段按可运行证据推进；每个切片记录实际用时、阻塞和返工，再调整预测。多 Agent 可并行适配器/解析器/测试，集群状态变更与集成验收串行。

## W0：隔离、骨架与契约（当前）

交付：deprecated 原样归档、独立 pyproject/uv.lock/.env.example、CLI status、核心 schema、架构/契约/阶段文档。

验收：归档逐文件 SHA-256 一致；旧 .env 不被新项目加载/纳入 Git；`uv run --frozen aiops --help` 和 status JSON 可用；`make check-all` 包含实际测试；新包没有 app/deprecated 导入。零测试通过不算完成。

## MVP：最小可验证闭环

MVP 用于尽早验证核心价值，不替代完整范围。它要求“可演示、可验证”，不是“功能最少”。

范围：

- 3 个代表性故障：OOMKilled（资源）、坏镜像（发布）、redis 延迟（依赖）。
- 每个场景至少两类独立信号，三个场景合计覆盖 metrics、logs、trace、Kubernetes events。
- 2 个动作：`restart_pod`、`rollout_undo`。
- 初步 eval：3 个场景，每个至少 3 次运行。

验收：

1. 三个场景可重复注入、判定和清理；注入真值与调查工具权限隔离。
2. 调查输出根因、证据引用和置信度；证据不足时如实输出 inconclusive。
3. 风险决策三态各至少出现一次：自动执行、等待审批、策略拒绝。
4. `restart_pod` 与 `rollout_undo` 各成功执行一次，并有执行后健康验证。
5. 至少一个场景输出 inconclusive 或被拒绝，不能把三场景全部报为成功。
6. eval 报告 Top-1/Top-3、工具调用、token、耗时；失败、拒绝与信息不足单独统计。
7. 一条命令可复现；报告记录版本、环境、模型与种子。

MVP 不包含：定时巡检、常驻服务、12 故障全集、PDF 知识库、`scale_replicas`、自动补偿、生产级 RBAC。这些留在后续阶段，不因 MVP 演示而删减完整范围。

## M1：OOM 垂直切片

先验证 k3d/五组件依赖/压测与采集，保存最小工作配置；接 PostgreSQL + 官方 LangGraph checkpoint、K8s/Prometheus 只读工具与最小假设循环。

交付：可重复的 OOM inject/verify/cleanup、调查与证据引用、动作前置检查/风险/审计、符合条件时的受控 Pod 重建与健康验证。

验收：正常基线 → 注入确认 → Agent 不见真值的调查 → 依据与结论 → 风险允许/等待/拒绝 → 执行与业务恢复验证 → 复位。持续 OOM 若重启无改善，必须报告失败/不适用并升级，不能让 harness 清理冒充自愈。

M1 允许两类真实来源，缺第三类时保留证据不足状态；不能为第一条切片临时降低全量验收标准。完整三类信号在 M2 检验。

## M2：遥测与调查扩展

交付：Loki/Tempo/OTel 与配套采集器、并行工具预算、更多故障、持久化 explain/context/hint。

验收：日志/指标/trace 的可追溯查询；噪声与反证用例；证据不足/超时/取消；hint 在检查点采纳；重启恢复调查而非重复开始。先跑小套件再扩展，不等 12 场景齐全才接 eval。

## M3：三动作、风险与恢复

交付：restart/scale/rollout 三适配器，自动/审批/拒绝策略，快照、验证、补偿、异常恢复、审计。

验收：低风险自动成功、中风险挂起并跨进程恢复、高风险拒绝；误判/无改善/恶化；补偿成功与失败；重复请求、过期审批、资源漂移、执行后崩溃。重启动作按不可逆处理。执行失败不能反复试到“绿”。

## M4：知识完整接入

交付：runbook、确认的事故记忆、文本 PDF 导入、pgvector 检索、文档版本/删除，真实来源引用。

验收：导入幂等、版本更新后旧片段不再召回、页码来源正确、无关文档/错误 runbook 不带偏；检索有标注集，无知识基线与有知识对照。扫描件不伪装成功。

## M5：常驻入口与完整故障集

交付：AlertManager + CLI + 定时巡检统一入口、12 场景、健康基线/巡检去重、独立常驻任务与恢复。

验收：无终端触发的端到端调查/处置；重复 alert 不重复写操作；巡检正常不制造 incident；重启服务后等待审批/运行任务可恢复。12 场景均可注入、判定与清理，不要求三动作能修复全部场景。

## M6：证据、评估与交付

交付：规则评分 + 辅助 judge + 人工抽检、Markdown/HTML 证据报告、演示与部署文档、CLI skill 使用说明。

验收：每个场景多次运行、成本/失败/拒绝/覆盖率分开统计；固定模型/版本/种子/环境，保存原始证据；恢复用健康探针和负载指标判定。外部通用 Harness + 相同工具/知识作为对照，比较正确性、恢复、误操作、成本与人工参与。

## 并行协作

每个 lane 以模块契约、输入输出、故障路径、验证命令为边界。独立 worktree，一个 writer；接口变更先合并契约。集成者核对代码和运行证据。只读研究可并行，故障注入/写操作同一环境串行。当前 W0 没有启动子 Agent 或常驻进程。
