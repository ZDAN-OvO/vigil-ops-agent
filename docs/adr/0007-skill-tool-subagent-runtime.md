# ADR-0007：在 create_agent 上装配排查方法、工具与委派调查

- 状态：已采纳（2026-11-13）
- 取代：[ADR-0005](0005-langchain-single-agent-loop.md) 中“固定 11 个工具与单一提示词”的部分；原决策记录中“显式假设树”“首版只有单 Agent”“只读追问”“规则基线对照”的相应条款
- 相关：[ADR-0002](0002-langgraph-orchestration.md)、[ADR-0004](0004-controlled-resource-actions.md)、[ADR-0006](0006-task-outcome-separation.md)、[词汇表](../../GLOSSARY.md)

## 背景

ADR-0005 已把调查主循环换成 LangChain `create_agent`，但能力装配是固定的：一份提示词、11 个工具、强制维护完整假设树。新增一类故障的排查做法就要改运行时代码，也无法把独立的子问题放到单独上下文中处理。产品定位是中小企业和个人开发者使用的 AIOps，排查能力需要能持续扩充，同时真实运维操作必须保持可靠、可追溯。

## 决定

1. **运行时**：继续使用 `create_agent` 提供的工具循环，不自行实现通用 Agent 循环。消息与 checkpoint 由 LangChain／LangGraph 持久化，项目不重复实现。
2. **排查方法（Skill）**：调查方法改写为可加载、带版本的 Skill，采用 [Agent Skills](https://agentskills.io/specification) 格式。本阶段只使用仓库内置 Skill，加载接口保留增加其他来源的能力。
3. **两种加载触发**：
   - 描述触发：由 Agent 根据 Skill 的 `description` 判断是否加载。
   - 信号触发：调查开始时，程序按事件来源或告警的 `alertname` 自动加载匹配的 Skill，规则写在 `metadata` 的 `vigil-` 前缀字段中，不经过模型判断。
   - hypothesis-driven Skill 绑定告警、CLI 手动调查和定时巡检三种来源；以后的对话入口由 Agent 按描述判断。每次调查记录所用 Skill 的名称和内容哈希。
4. **工具**：注册方式不依赖 Kubernetes；首批只提供 Kubernetes 与 Prometheus 的只读工具，以及假设、证据和动作请求工具。
5. **委派调查（Subagent）**：只读，共享主调查的预算与权限；同一时间最多运行一个；处置只能由主 Agent 发起。委派产生的观测写入同一观测记录，并标注来源委派。
6. **处置约束不随 Skill 变化**：任何入口提出的动作都必须引用一个假设及支持它的观测，由程序校验，要求写在动作请求工具的说明中。动作范围、风险策略、审批与执行器保持不变。
7. **数据分工**：运行时需要读取的数据和需要长期保存的操作记录放业务库；只用于人工排错和成本分析的数据交给可选的追踪平台（LangSmith 或 Langfuse），默认关闭，业务正确性不依赖它。

## 考虑过的选项

- **把 hypothesis-driven 只写成 Skill 文本，不做结构化存储**：动作依据与复盘只能解析自由文本，无法校验“处置依据了哪个解释和哪条观测”。因此保留轻量的假设与证据关系。
- **保留完整假设树与修订历史**：会把调查方法写死在数据结构里，与“方法放在 Skill 中”冲突。
- **由追踪平台承担审计与恢复数据**：默认保留期为 14～30 天，可能被关闭或抽样，且不含审批、取消等人工操作，不能满足恢复、防重复执行和长期审计的要求。
- **允许委派调查直接处置或并行运行**：会出现多条授权和执行链，并引入共享预算的并发问题；留到证明账本与预算在并发下正确之后再考虑。

## 后果

- 业务表调整：保留事件、调查、任务状态、工具账本、观测、提案、审批、执行、锁、待办与 Runbook；假设和证据关系简化保留；`audit_events` 只记录业务事件；新增委派调查记录；停用 `hypothesis_revisions`、`evidence`、`tool_calls`。旧调查数据不迁移，新代码不保证读取旧调查与旧报告。
- 移除只读追问 `explain`、规则基线与完整 MVP 验收评分器；入口只保留 CLI 与 AlertManager webhook。相对规则基线和通用 Agent 的收益证明推迟到新数据模型稳定后重建，要求本身不取消。
- 前端、持续对话、上下文工程、运行中追加提示、用户自定义或远程 Skill、新动作、新环境和并行委派都不在本阶段范围。
- 验收沿用上一轮真实环境标准：坏发布、持续 OOM、Redis 访问链路延迟各至少 3 次有效运行且各至少 1 次调查正确；前两者至少各 1 次业务恢复，Redis 场景正确停止且不写；Pod 重建场景至少 1 次由 Agent 自主重建且 UID 改变、模板不变；审批跨进程恢复和重放不二次写各有真实记录；至少 1 次运行实际使用委派调查并可回查委派目标、所用 Skill 与返回观测；`make check-all` 通过。验收结果见[路线图](../ROADMAP.md)。
- 预算沿用 [ADR-0011](0011-investigation-budget.md)，委派与主 Agent 共享；若真实验收中预算成为失败主因，按该 ADR 的方法重测定值。
