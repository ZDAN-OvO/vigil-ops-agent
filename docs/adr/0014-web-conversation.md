# ADR-0014 本机 Web 对话和单一推进者

状态：已采用

首版需要把故障描述、补充线索、证据、审批和业务验证放在同一个工作区。调查引擎和受控执行器继续复用。页面进程运行时，一次集群处置需要由用户在对应提案卡片上作出批准决定。

## 决策

- Web 接口使用 FastAPI。请求和响应使用独立类型，由 OpenAPI 生成 TypeScript 声明。告警仍在自己的应用和监听口处理。
- 页面绑定回环地址，检查 Host 和写请求 Origin，并禁止嵌入。审批校验卡片指纹并在一个事务中保存决定、审计和续跑工作。
- 本机进程锁隔离服务与开发写命令。后台工作、租约、审批就绪和恢复状态由 PostgreSQL 持久化。
- 快照从业务表读取，SSE 提醒重拉。刷新、断线和重启继续使用同一数据库状态。

## 取舍

继续使用 Starlette 会减少一个依赖，需要单独维护请求校验、错误体和类型文档。FastAPI 统一了这些契约。两种应用分别监听，使告警端口不暴露页面。

数据库租约受连接状态影响。进程锁覆盖正在写集群的进程及继承锁的实验子进程，任务租约协调数据库里的工作交接。服务重启时，未决写入进入人工核实流程。

首版按同一主机运行并共享锁文件来提供互斥。页面仅显示当前会话。涉及远程或多实例部署时，需要重新设计访问控制和写入协调。
