# 由 Agent 按巡检 SOP 主动运维

Vigil 的主动巡检定位为运维人员的例行工作：Agent 按可版本化的巡检 Skill 执行 SOP，周期性巡查登记服务、节点和入口；确定性预筛只把异常交给单个 Agent 主线处理。写权限仍由 YAML 处置策略登记，SOP 文本只是流程指导，不是授权来源。

巡检产生的观察作为处置规则证据；命中登记的巡检处置规则时，动作和参数由规则给出，Agent 只负责解释、核对证据和验证结果。Agent 不根据巡检观察自由改写参数。这样复用既有风险决策、动作锁和补偿机制，避免把自然语言 SOP 变成隐式授权。

本决策补充 [ADR-0008](0008-product-scope-and-lab.md) 的触发范围；安全边界沿用 [ADR-0013](0013-controlled-auto-remediation.md)。

## Decisions

- 主动巡检在 `vigil serve` 中显式启用，默认关闭；启用后的默认间隔为 15 分钟，每轮默认最长执行 10 分钟。
- 一轮巡检是一个巡检会话；上一轮未结束时跳过本轮，重启后进行中的会话标记为中断。
- 每轮巡检留下可查询的巡检摘要；单项采集失败或数据超过登记的新鲜度阈值时记为信息不足，不触发自动处置。
- 确定性预筛先处理巡检观察；异常才交给单个 Agent 主线调查和解释。
- 巡检处置规则是新的规则类型，不伪装成告警规则；动作和参数由规则登记，Agent 只核对证据、解释处置并验证结果。
- 同一巡检故障按目标身份聚合；目标持续异常期间只允许一条活动故障和一次自动处置，恢复后关闭并解锁。
- 巡检与告警共用目标故障账本和原动作发送名额。持久化的巡检观察关联至该故障，证实恢复后才可结案。
- 巡检会话按创建时间和会话 ID 翻页。网页和命令行可回放，人工输入和审批由服务端拒绝。
- 轮次截止后停止采集、调查与授予新发送权。已取得发送权的动作由处置账本继续观察，业务验证和补偿回执追加到原会话。处置未恢复时停止重复处置，确认恶化后按既有机制补偿。

## Consequences

目标级聚合优先保证同一底层故障不会被多条规则拆分并重复处置；代价是同一目标上并发的真实故障会先作为一条巡检故障处理，其余观察保留在证据中。后续如需区分并发故障，必须引入可校验的故障分类，而不是放开重复处置。

第一版验收使用假时钟的自动化端到端测试：覆盖主动触发、巡查、规则命中、受控处置、结果验证、同故障限频和正常巡检摘要。
