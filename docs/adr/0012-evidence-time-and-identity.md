# ADR-0012：调查证据绑定时间窗与对象身份

- 状态：已采纳（2026-11-17）
- 相关：[ADR-0007](0007-skill-tool-subagent-runtime.md)、[ADR-0009](0009-risk-verification-and-stop.md)、[ADR-0011](0011-investigation-budget.md)

## 背景

2026-11-15 的 Pod 重建手动调查第 3 轮把上一轮重建事件与本轮再次注入后的 500 连成同一次恢复对照，错误反驳了 Pod 局部状态假设，最终以信息不足结束。调查本身没有选错 Skill，失败发生在证据时序判断。

当时的事件观测只带对象名称，不带对象 UID；提示词也没有要求把事件时间、对象身份和当前目标对齐。同一工作负载连续重建时，旧 Pod 的事件仍在回看窗内，模型仅凭名称和现象时间无法可靠区分“上一轮的动作”和“本轮的故障”。

## 决策

1. `kubernetes.list_events` 的裁剪结果包含 `involved.uid`，让模型能核对事件对象是否就是当前目标。
2. 系统提示词要求：判断动作是否有效或故障是否持续时，事件类证据必须核对发生时间和对象 UID；不同 UID 的历史事件只能作背景。日志、业务请求和 Service 观测按采集时间与目标工作负载关联，不因为拿不到 UID 就丢弃有效业务证据。
3. `pod-rebuild` Skill 的“必须核对”加入事件与观测的时间、对象 UID。
4. 真实验收每轮重建命名空间，避免上一轮事件留在回看窗内。
5. 只读工具的模型可见结果返回 `collected_at` 与 `time_range`；同参缓存复用原采集时间，避免模型把旧结果当成新观测。
6. 动作依据校验失败时，错误结果列出该假设当前可用的支持观测与被引用观测的实际关系，让模型能自我纠正，而不是重复同一个错误引用。

不改变 Skill 加载机制、默认预算和动作规则。

## 备选方案

- **只隔离验收环境**：能消除本轮污染，但生产环境仍可能在同一工作负载上看到历史事件，不能只靠实验流程。
- **只改提示词**：模型拿不到对象 UID，仍可能把同名工作负载的旧事件当成本轮证据。
- **按事件时间过滤**：上一轮事件仍可能落在 15 分钟回看窗内，过滤不能解决；还会隐藏有用的历史背景。
- **缩短回看窗**：治标，可能漏掉故障前兆，也没有解决对象身份问题。

## 后果

- 事件观测多一个 UID 字段，模型需要主动比较；提示词和 Skill 各增加一条约束。
- 工具消息多两个时间字段；同参缓存保留原采集时间，模型需要自己判断结果是否过期。
- 动作依据错误消息更长，但模型能在一次拒绝后改用有效观测；2026-11-17 第 4 轮因此暴露、第 5 轮复验通过。
- 验收每轮多一次命名空间重建，约一分钟；这是实验隔离成本，不影响产品运行。
- 2026-11-17 五轮补充验收中四轮自主选中 `pod-rebuild`、确认根因并恢复；第 4 轮动作依据引用错误，修复后第 5 轮复验通过。详见[运行记录](../../faults/a01-pod-rebuild/runs/2026-11-17.md)。样本仍小，不据此宣布普遍稳定性通过。
