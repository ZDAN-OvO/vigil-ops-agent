# 由预定义规则授权自动处置和补偿

Vigil 可以直接调整 Kubernetes 工作负载的内存或 CPU、实例数，以及指定的环境变量或配置项。三类动作可以恢复本次变更前的原值。版本管理的 YAML 登记服务、故障规则、证据要求、自动执行范围和禁改项，由人维护。

先判硬性禁令。命中规则、证据齐全、参数在自动执行范围内且已取得原值时，免人工审批。Agent 可以提出规则范围之外的建议，由人审批普通且可审查的变更。高危动作直接拒绝，审批无法放行。Vigil 使用专用 ServiceAccount，集群按命名空间、资源类型和动词限制权限，并限制允许写入的字段。

同一故障最多自动处置一次。等待变更生效后，用真实业务探针、故障信号和观察窗判定结果。出现能归因于处置的明确恶化时，最多自动补偿一次。无改善、结果未知或补偿失败时，停止自动动作并通知人工。默认观察窗为 10 分钟，每分钟一次业务探针，规则可覆盖观察窗长度。

采用逐项变更，可以记录精确原值，并在撤回时保留其他人做的变更。只提审批卡会延迟已知故障的恢复。整版本回退会同时改动无关字段，范围更难约束。

本决策取代 [ADR-0004](0004-controlled-resource-actions.md) 的动作范围，更新 [ADR-0009](0009-risk-verification-and-stop.md) 中的自动执行、观察与补偿规则。Pod 删除和整模板回退停止通过 Vigil 写入。禁止改动 PVC、Secret、RBAC、ServiceAccount、镜像和启动命令，禁止删除资源及越出登记命名空间。Vigil 直接修改 Kubernetes，本期范围止于上述三类动作。
