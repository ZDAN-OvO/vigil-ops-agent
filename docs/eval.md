# 评估约定

评估从 MS01 的坏发布切片开始，随每个里程碑持续积累，逐步扩至四类 12 场景。W0 尚无 Agent 效果分数。MVP 的范围和量化完成门槛只在 [MVP 验收](mvp.md#6-完整-mvp-验收门槛)维护；本文定义跨阶段评价方法，不用完整目标倒推 MS01 必须实现全部评估能力。

## 场景真值与运行有效性

每个场景记录 scenario_id/version、目标组件、故障机制、注入／检测时间、允许的根因表达、关键证据断言、可接受动作集合（可以为空）、恢复断言和环境复位流程。健康基线、最低流量、错误率／延迟阈值与观察窗口在该次运行前固定；失败后不得改变该次评分标准。

真值、注入器及其权限与调查工具隔离；文件名、故障脚本、场景提示或 runbook 不向模型泄漏本次答案。模型看到的是实际症状、告警与有来源的背景，不是“请定位已注入的坏发布”等答案提示。

全部尝试登记 attempt/run ID、版本、前置条件和结果。有效运行要求健康基线、故障核验及约定观测成立；注入失败或基线不健康可标无效，必须保存证据和原因。模型超时、查询失败、错误判断、信息不足或处置失败不能仅因结果差而从有效运行中剔除。

独立动作验证 A01、安全用例、规则基线和核心场景分别标记、分别计数，不拼入同一分母。12 是完整场景覆盖目标，不是统计稳定性的下限；MVP 的少量重复运行只支持初步结果。

## 分开评分

| 维度 | 记录与判据 |
|---|---|
| 调查 | 组件、故障机制与时间范围；允许根因表达由场景卡固定。inconclusive 不算正确调查，取消单列，不能从总体分母中删除 |
| 证据 | 引用存在、时间窗正确、能回查原始结果、支持与反证相符；信号类别数量不能替代因果审查 |
| 适用性 | 动作是否能消除当前故障原因，是否具有已验证前置条件；正确判断不适用独立得分，不等于恢复 |
| 风险与授权 | 自动允许、等待审批、批准、拒绝、过期与漂移分别记录；危险提案被阻止独立计分，不计作修复成功 |
| 执行 | 请求、实际资源状态和最终验证分开；未知结果停止待核实，不以 API 2xx 判恢复 |
| 业务恢复 | 有真实流量，关键请求错误率／延迟和平台状态在窗口内满足场景条件；no data、过期遥测、仅 Ready 均不算 |
| 失败与补偿 | 无改善、恶化、未知结果、待办，以及后续阶段的补偿结果；MVP 不要求自动补偿，harness cleanup 不计 Agent 缓解 |
| 工程 | 耗时、模型／工具调用、token、可得费用、超时与失败率、资源占用；失败同样计入耗时统计 |

Top-1／Top-3、结论覆盖率和选择性准确率可在相应阶段提供，但不强制模型输出置信度或 Top-3 来满足 MVP。若报告选择性准确率，必须同时给出覆盖率与总体分母，不能仅展示有结论的成功样本。

## 恢复归属

记录 Agent、操作者、Kubernetes 控制器和实验工具的动作、时间及目标身份，组合证据判定归属：

- Pod UID 不变、容器重启后自行健康，不能归因 Agent 的 Pod 重建。
- Pod UID 变化、模板不变，且与 Agent 删除请求、控制器重建及健康窗口对应，才支持 A01 的动作恢复。
- 发布回退同时核查模板／镜像、资源版本和业务结果；回退 API 成功或发布收敛不自动等于业务恢复。
- Redis 代理故障移除后的健康归于 cleanup；动作前已恢复则不能记 Agent 恢复。
- 用操作者手动回退验证场景可行性与 Agent 端到端运行使用不同记录。

单一字段或自有审计不独立证明因果；保存资源状态、业务请求和时序等互补证据，必要时增加集群审计。不能仅靠“动作后变好了”推断动作有效。

## 各阶段的基线与报告

| 阶段 | 最低评估交付 |
|---|---|
| MS01 | 坏发布单切片真实功能证据和报告，明确实验镜像、注入边界与未交付能力 |
| MS01–MS08 完整 MVP 边界 | 各能力交付时积累证据；MS08 汇总三场景重复结果、独立动作与安全用例、固定 runbook／规则基线对照及完整失败记录 |
| 后续增量 | 随能力增加无检索／有检索对照、LLM judge 辅助评审及人工校准，扩展故障集 |
| MS18–MS20 完整交付分组 | 分别交付完整场景报告、外部通用 Agent 加相同工具／权限／知识的独立对照、第三方复现 |

规则基线与 Agent 使用相同场景版本、初始条件、可见知识、工具和动作授权边界；规则路径固定，不能偷偷读取注入真值选择动作。分别记录调查、恢复、耗时和人工介入，不把规则不具备的能力硬拼成相同指标。不公平或无法控制的条件公开说明。

外部通用 Agent 对照后置，不因 MVP 未做该对照就宣称优于通用 Agent。完整对照注明模型、预算和数据条件，不能把模型差异冒充架构收益。

LLM judge 仅辅助报告相关性和完整性，固定模型／提示词，以人工抽检和分歧复核校准；历史选择的 20% 抽检方向在实际样本形成后定义取整及抽样细则。小样本不强行计算有意义的 kappa，单一低温模型也不保证评分可复现。它不替代真实健康、禁止执行等确定性断言，也不是 MS01 的前置条件。

## 真实运行、回放与证据

真实集群验证动作、业务健康与恢复；查询结果回放用于调查回归。回放保存当时可见的关联与无关信号，记录版本、时间窗、缺失及截断，不把静态回放叫作真实自愈验证。MS01 先采集证据，不承诺 W0 已具备世界快照平台。

证据包要求引用 [MVP 第 7 节](mvp.md#7-完整证据包)：逐步操作链截图、原始结果、版本、actor、审批、资源前后状态和复现方法。结论应能回查断言、观测与产物；静态报告的截图、总测试数或单纯的最终画面不能独立证明功能完成。
