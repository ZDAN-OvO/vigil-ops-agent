# 评估约定

评估从 M1 的单切片开始，逐步扩至 12 场景。W0 尚无 Agent 效果分数。

## 场景真值

每个场景记录 scenario_id/version、目标组件、故障机制、注入/检测时间、允许的根因表达、关键证据断言、可接受动作集合（可以为空）、恢复断言、环境复位流程。真值和注入器权限与调查工具隔离；报告文件名也不向 Agent 泄漏答案。

12 是场景覆盖目标，不是统计稳定性的下限。每个场景重复运行，逐场景报告成功/失败；小样本比例同时报告分母，不声称生产总体准确率。

## 分开评分

- 调查：组件/故障机制/时间窗分别评分；Top-1、Top-3、结论覆盖率与选择性准确率分开。inconclusive 不算成功，不能从总体分母中删除。
- 证据：引用存在、时间窗正确、能回查原始结果、支持/反证是否对应；类别数量不能替代因果审查。
- 处置：动作是否适用、策略是否允许、是否需要人工、执行后业务是否恢复；拒绝危险提案有独立安全得分，不计作修复成功。
- 恢复：恶化检测、补偿结果、补偿失败升级；harness cleanup 不计 Agent 缓解。
- 工程：耗时、模型/工具调用、token、可得费用、超时与失败率、资源使用；失败也计入耗时统计。

LLM judge 仅辅助报告相关性和完整性，固定模型/提示词，人工抽检与分歧复核；小样本不强行计算有意义的 kappa。单一低温模型不保证评分可复现。

## 基线

至少比较固定 runbook/规则基线、无检索 Agent、有检索 Agent；外部 Harness + 相同工具/权限/知识使用独立运行记录作产品必要性的对照。模型、预算和数据条件注明，不能把模型差异冒充架构收益。

## 真实运行与回放

真实集群验证动作/健康/恢复；查询结果回放验证调查回归。回放保存当时可见的关联与无关信号，记录版本、时间窗与缺失数据；不把静态结果回放叫作真实自愈验证。首次切片先采证据，不承诺 W0 已具备 world snapshot 平台。
