# 里程碑与验收

状态：按用户确认的“每个可达阶段交付一项完整能力”重新划分；2026-11-08 已完成 MS01–MS08，V01–V10 在真实实验上满足，完整 MVP 已交付；MS09–MS20 待实现。数量来自能力边界，不是交付日期或工作量承诺。

本文维护能力、依赖与验收出口；[MVP 范围与验收](mvp.md)维护场景及统一门槛，[滚动迭代计划](iterations.md)维护当前怎样到达下一里程碑，[评估约定](eval.md)维护评分方法。每项里程碑引用统一标准，不复制另一套验收清单。

## 层级与完成规则

- **阶段**：组织方向和优先级，只作为分组，不再用一个阶段编号包住多项交付。
- **里程碑**：完成后，操作者新增一项可独立操作、展示和验收的能力。环境、表结构、客户端接入等属于实施任务或实验关卡。
- **迭代**：围绕当前目标里程碑安排实验、开发和集成，可跨多轮迭代；任务状态在 GitHub Issues 维护。
- **交付边界**：两周展示目标是 MS01；完整 MVP 要求 MS01–MS08 全部通过且 [V01–V10](mvp.md#6-完整-mvp-验收门槛) 满足。MVP 本身不再作为一个包住所有功能的里程碑。
- **完成证据**：每项有真实操作链、关键异常路径和可回查产物。安全、授权、幂等、失败停止随当前功能一起验收，不等到“可靠性阶段”才补。
- **时间与顺序**：保留两周展示窗口，完整 MVP 无两周承诺；默认可靠性优先。阶段内编号给出推荐推进顺序，具体可启动条件看前置依赖，不把编号误当所有能力必须串行完成。

W0 是已有工程基线：根目录独立项目、CLI status、配置、值对象和本地质量检查。它不计入下面的产品里程碑，也不证明集群或业务能力已完成。迁移证据限制见[迁移记录](migration.md)。

## 两周展示

### MS01：坏发布告警到业务恢复

- **新增能力**：操作者能看到真实业务异常自动触发调查，审查证据和受控发布回退，确认业务恢复。
- **前置依赖**：W0；真实浏览、加购和购物车路径、负载、两类互补信号、告警、模型和健康／故障镜像通过实验关卡。具体记录见[迭代计划](iterations.md)的 I01 切片记录。
- **完整操作链**：健康基线 → 坏发布与故障核验 → AlertManager／webhook → 假设调查 → 提案与规则／人工授权 → 受控回退 → 业务观察 → CLI／静态报告 → 结果判定后复位。
- **验收出口**：通过 [MVP 两周展示链路](mvp.md#4-两周展示链路)；Context 可提供并核实，目标、授权、幂等、执行意图、审计和失败停止随链路验收。危险或无效提案不执行，重复请求不重复写，未知结果停止待核实。
- **证据**：F01 完整证据包、初始和中间状态截图、真实告警、原始查询、动作 actor／版本及业务恢复窗口；不能用人工回退实验代替 Agent 运行。
- **范围边界**：不含审批跨进程恢复、runbook、Explain 或三场景重复对照；这些由后续里程碑交付。展示时未通过就说明实际阶段和阻塞，不降低标准。该项链路较长，因为缺少任一核心环节就无法证明“两周展示”的目标价值；内部检查点由迭代管理。

## 完整 MVP

### MS02：审批跨进程继续

- **新增能力**：操作者退出进程后仍可找回待审批提案，批准或拒绝，并安全继续原流程。
- **前置依赖**：MS01 的提案、执行意图、授权和记录。
- **完整操作链**：提案待审 → 关闭进程 → 重启并查询 → 批准／拒绝 → 重新校验 → 单次执行或停止 → 验证和报告。
- **验收出口**：提案与决定持久化；审批绑定目标和范围；过期、资源漂移、参数变化不会沿用无效授权；重复批准不重复写。批准、拒绝和失效路径均有证据，对应 V04、V05、V07。
- **证据**：跨进程命令记录、同一提案的前后状态、授权与资源版本、集群动作及健康观测。
- **范围边界**：审批等待恢复不等于执行中断自动协调；后者在 MS09。执行结果不确定时停止不能后置。

### MS03：持续 OOM 调查与处置判断

- **新增能力**：操作者能得到内存限额不足的证据及适用性判断，而不是无效重启建议。
- **前置依赖**：MS01 的真实取证和动作链；F02 注入与复位实验成立。
- **完整操作链**：健康基线 → 降低实验内存限额 → OOM／业务受损告警 → 调查规格原因 → 重建不适用判断 → 符合条件回退并验证，或停止留待办 → 复位。
- **验收出口**：按 [F02](mvp.md#f02持续内存限额不足导致-oom) 验证两类互补信号、原因和适用性；不能把 K8s 自恢复算 Agent 恢复；未授权的任意内存配置修改不可执行。
- **证据**：独立真值、终止原因与限额、真实业务请求、假设和反证、提案／停止原因及结果。
- **范围边界**：不要求删除 Pod 修复 OOM；实际参数在实验中固化。达到重复次数和统计要求由 MS08 总体验收，不妨碍当前先证明完整能力。

### MS04：Redis 访问链路延迟调查

- **新增能力**：操作者能区分依赖链路变慢与 Redis 服务端原因，并得到有依据的不处置结论。
- **前置依赖**：MS01 的取证、停止与报告链；非特权代理及依赖观测实验成立。
- **完整操作链**：健康基线 → 代理保持延迟 → 业务异常 → 关联业务与依赖证据 → 限定根因候选范围 → 不适用判断／人工待办 → 判定后清理并验证。
- **验收出口**：按 [F03](mvp.md#f03redis-访问链路延迟) 验证；没有服务端证据不声称 Redis 内部阻塞，现有动作无法移除延迟时不得反复尝试，代理清理后的健康不计 Agent 恢复。
- **证据**：业务指标和日志／trace、故障持续性、停止记录、Agent 与 cleanup 的独立时间线。
- **范围边界**：不引入任意网络写操作或宿主特权；新增注入机制需重新确认。

### MS05：Pod 重建恢复验证

- **新增能力**：操作者能在明确适用、无状态的条件下授权重建 Pod，并验证其消除了故障。
- **前置依赖**：MS01 的执行与健康验证；A01 机制证明故障跨容器重启持续、Pod 重建消除。
- **完整操作链**：专用负载健康 → 临时故障持续 → 调查与适用性判断 → 授权删除指定 Pod → 控制器重建 → UID 与业务验证 → 报告／复位。
- **验收出口**：按 [A01](mvp.md#a01pod-重建动作的独立验证用例)；不同 Pod UID、同一模板、真实请求恢复且清理未提前介入，删除不可逆前置限制通过。仅 API 成功、`rollout restart` 或自然恢复不能通过。
- **证据**：独立真值、actor／时间、Pod UID／模板前后记录、真实请求及健康窗口。
- **范围边界**：只证明受限动作适用性，不证明重启能修复 OOM；独立于核心三场景分母，不丢弃真实业务数据。

### MS06：Runbook 辅助调查

- **新增能力**：调查能查询少量结构化排查知识，核实并引用来源。
- **前置依赖**：MS01 的真实调查和证据引用。
- **完整操作链**：登记结构化 runbook → 查询候选条目 → 调查取证核实 → 引用或反驳 → 输出报告。
- **验收出口**：来源可回查，建议仍过规则；无关或错误 runbook、错误 Context 不直接成为证据或授权；本次场景真值不泄漏。对应 V08 的 runbook 与背景核实部分。
- **证据**：知识版本、查询与原文、采纳／拒绝理由、实际工具结果及报告。
- **范围边界**：先简单结构化检索，不以向量检索、事故或 PDF 导入为前置；pgvector 完整方向保留。

### MS07：调查结果只读追问

- **新增能力**：操作者可问“为什么这样判断”，获得带已有证据引用的回答。
- **前置依赖**：MS01 的持久调查与证据；不以 MS06 为硬依赖。
- **完整操作链**：选择已完成调查 → CLI 提问 → 查询可见记录 → 引用回答或说明不足 → 核对原结论与资源未改变。
- **验收出口**：引用存在且范围正确，不凭空补事实；缺信息就说明，需新查询时显式提出续查，不静默取证或执行。对应 V08 的 Explain 部分。
- **证据**：追问输入／输出、引用原文、前后记录与工具／写操作审计，覆盖缺证据问题。
- **范围边界**：只读 Explain；运行中 Hint 在 MS14，不扩展为聊天界面。

### MS08：重复评估与规则基线

- **新增能力**：操作者能重复运行约定场景，与固定规则比较，并判断完整 MVP 是否达到门槛。
- **前置依赖**：MS01–MS07 的能力证据与场景版本；评估记录从各里程碑就开始积累。
- **完整操作链**：冻结场景与参数 → 独立多次运行 Agent／规则基线 → 规则评分 → 核对失败与分母 → 汇总报告 → 审核 MVP 总门槛。
- **验收出口**：[V01–V10](mvp.md#6-完整-mvp-验收门槛) 全部满足；每核心场景至少三次有效运行、至少一次正确调查，两动作各真实成功；禁止、证据不足、审批恢复等关键行为单独通过。全部尝试保留，规则不读取真值选动作。
- **证据**：逐次结果、无效理由、基线独立运行记录、失败原始材料、耗时／用量／人工介入和总验收对应表。
- **范围边界**：达到这里才可宣布完整 MVP；最低次数不代表稳定可靠，不能宣称优于通用 Agent。LLM judge 与完整对照后续增量接入。

## 处置可靠性

### MS09：执行中断后核实结果

- **新增能力**：处置进程中断后，系统先核实真实状态再收敛，操作者不必猜测写请求是否生效。
- **前置依赖**：完整 MVP 的执行意图、目标互斥、幂等、审批和未知结果停止行为。
- **完整操作链**：提交动作 → 在写前或请求后中断 → 重启 → 关联持久意图与真实资源 → 验证／停止待核实 → 记录结果。
- **验收出口**：真实写前中断、写后未知、重复请求、目标漂移均不盲目重放；能够核实的结果收敛，无法核实的结果保持未知并升级，不误报失败或成功。
- **证据**：中断位置、数据库意图、集群请求与资源前后状态、重启记录和业务验证。
- **范围边界**：不承诺任意动作自动恢复或跨动作事务；异常路径的可靠性需要相应真实环境证据。

### MS10：处置恶化后的限定补偿

- **新增能力**：适用动作导致失败或恶化时，系统恢复声明范围内的状态并再次验证，失败则停止升级。
- **前置依赖**：MS09 的结果协调、动作前快照和健康验证。
- **完整操作链**：受控处置 → 观测恶化 → 判断可补偿性及并发变化 → 限定字段补偿 → 再验证 → 记录或人工升级。
- **验收出口**：至少验证适用的发布动作补偿、无改善时的处理、不支持补偿、并发修改阻止、补偿失败停止；不盲目覆盖旧对象，不反复补偿到绿。
- **证据**：前快照、动作／补偿意图与实际状态、恶化和再验证、失败待办。
- **范围边界**：Pod 重建不可逆，不提供假 undo；不恢复业务数据，不承诺跨动作事务。故障发布回退是处置，撤销其影响才是补偿。

### MS11：受控扩缩容

- **新增能力**：操作者可让系统针对适用异常提出并执行限定扩缩容，验证业务效果或安全恢复原副本数。
- **前置依赖**：MS09、MS10；将补偿边界扩展到副本字段前先对齐契约。
- **完整操作链**：适用异常 → 证据与副本提案 → HPA／资源／并发前置检查 → 风险和授权 → scale → 业务验证 → 必要且安全时恢复副本数。
- **验收出口**：真实成功、无改善、HPA 冲突、外部修改、执行中断和补偿路径；只恢复声明字段，不把扩缩容当作所有延迟的通用修复。
- **证据**：版本化适用用例、提案、HPA／资源和副本前后状态、请求指标与补偿记录。
- **范围边界**：完整目标的第三动作，不改变 MVP 两动作门槛；具体故障机制与阈值在本阶段实验细化。

## 持续运行

### MS12：常驻告警任务恢复

- **新增能力**：没有交互终端时服务仍能接收、关联和处理告警，重启后任务可追踪且不重复处置。
- **前置依赖**：完整 MVP、MS09；默认先完成处置可靠性分组，再展开本阶段。
- **完整操作链**：重复／关联告警 → 事件与任务 → 领取 → 调查／等待审批 → 中断服务 → 恢复或核实 → 报告与待办。
- **验收出口**：无终端触发真实链路；重复 alert 不重复写，待审和运行任务不丢失；任务失败和领取重试有边界，不能把一次 CLI 运行称为常驻能力。
- **证据**：外部触发、任务与事件关联、服务重启、同一动作的实际执行次数及恢复记录。
- **范围边界**：本机实验常驻能力，不宣称高可用或生产治理；MVP 最小 webhook 已存在，不重复算作新增交付。

### MS13：定时巡检发现异常

- **新增能力**：系统能在没有告警通知时按基线发现异常，并通过统一入口进入调查。
- **前置依赖**：MS12 的常驻任务及事件关联。
- **完整操作链**：定时运行 → 健康基线比较 → 正常记录／异常关联或创建事件 → 调查 → 结果报告。
- **验收出口**：正常不制造事件，持续相同异常不反复创建处置，真实异常可进入既有调查与风险链；缺数据不当成健康或确定故障。
- **证据**：调度时刻、基线／观测、正常与异常连续运行、去重和调查关联。
- **范围边界**：巡检条件、窗口和频率在本阶段实验固化；不以固定演示异常覆盖所有故障。

### MS14：调查中追加提示

- **新增能力**：操作者能给运行中的调查追加线索，重启后仍可追溯何时采纳及影响。
- **前置依赖**：MS02 的授权边界、MS12 的运行任务恢复。
- **完整操作链**：运行调查 → CLI 提交 Hint → 持久化 → 安全检查点消费 → 核实取证 → 记录采纳／拒绝 → 更新报告。
- **验收出口**：来源、提交与采纳时刻可查，重复和中断不重复消费；错误提示不能冒充证据，改变动作参数时重新提案与授权。
- **证据**：Hint 和任务状态、消费位置、真实查询、已审批提案前后状态。
- **范围边界**：不支持借 Hint 任意修改已批准动作，不与只读 Explain 混用。

## 知识扩展

### MS15：确认事故辅助调查

- **新增能力**：操作者确认的历史事故可作为可追溯知识辅助新调查和追问。
- **前置依赖**：MS06 的知识引用、MS07 的解释与持久调查。
- **完整操作链**：调查结果与证据 → 人工确认 → 登记事故知识 → 新调查检索 → 核实并引用 → 更新或撤销确认。
- **验收出口**：保存症状、根因、解决方法、来源与确认状态；未经验证的模型结论不能自动进入可信知识；过时、无关事故不直接带偏。
- **证据**：确认与版本记录、查询原文、正反例调查及引用、撤销后检索结果。
- **范围边界**：确认只表示该历史记录的可信来源，不等于新事件根因已成立；具体记录生命周期在实施前补齐契约。

### MS16：PDF 知识完整生命周期

- **新增能力**：操作者导入文本 PDF 后，能在调查与追问中引用正确页码，并可靠更新和删除知识。
- **前置依赖**：MS06、MS07；PostgreSQL + pgvector 与 embedding、版本／距离契约实验可用。
- **完整操作链**：导入 → 检索并引用 → 重复导入 → 更新版本 → 再查询 → 删除 → 验证不再召回。
- **验收出口**：幂等、正确页码和来源，旧版本和已删片段不再召回；不支持扫描件／版式时如实报告。用标注检索集检验相关与无关知识，过滤不能冒充企业权限。
- **证据**：文本原页、文档／chunk 版本、查询结果、更新删除前后记录与检索评分。
- **范围边界**：先一份完整生命周期，再扩量和验证混合检索；不预先承诺规模或性能，换 embedding 必须重建索引。

## 完整交付

下面仍是独立能力里程碑。故障清单、对照样本与第三方环境尚未验证，只写验收边界；临近实施时再拆可独立验收的新增能力，不虚构所有远期任务。

### MS17：跨信号追溯一次调查

- **新增能力**：操作者能从一次调查的时间窗、目标和证据引用回查相关指标、日志和 trace，辨认支持、反证和缺口。
- **前置依赖**：MS01；按 MS03、MS04 等需要增量接入，达到完整验收时全栈可用。
- **完整操作链**：真实业务异常 → 相关信号采集 → 有界查询 → 跨来源核实 → 报告引用 → 原始观测回查。
- **验收出口**：完整目标的 Prometheus／AlertManager／Loki／Tempo 及必要采集器接入；指标、日志、trace 均有真实查询和可回查出处；噪声、缺失、过期和截断不伪装充分证据。
- **证据**：同一次运行的目标／时间窗、实际查询、原始引用、资源与采集配置版本及噪声反例。
- **范围边界**：不要求每种故障都有全部信号，也不为凑数量编造 OOM Event；平台对象与派生指标相关性明确说明。

### MS18：完整故障覆盖与效果报告

- **新增能力**：操作者能运行四类 12 个有独立机制的场景，查看每类定位、处置和恢复的真实效果。
- **前置依赖**：MS03–MS05、MS08、MS11、MS17；场景在此前里程碑持续增量加入。
- **完整操作链**：选择版本化场景 → 注入／核验 → 调查与适用处置 → 结果评分 → 复位 → 重复运行 → 汇总各场景分母和失败。
- **验收出口**：12 场景均可注入、核验和复位，不换名凑数；不要求三动作修复全部故障。覆盖、拒绝、不适用、信息不足、恢复、成本分别统计；真实运行和回放分开。
- **证据**：逐场景机制卡、原始运行与结果、固定版本和用量、补偿／清理归属及报告。
- **范围边界**：具体 12 项尚未全部定义，依据实际业务能力补齐；增加机制先审查场景卡，不在此虚构注入方法和时间承诺。

### MS19：同条件方案对照

- **新增能力**：读者能在公开条件下比较知识接入、专用流程与通用 Agent，判断收益及代价。
- **前置依赖**：MS08 的规则基线，MS15–MS18 的知识、遥测和故障证据。
- **完整操作链**：冻结模型／工具／权限／知识／预算条件 → 无检索／有检索及外部通用 Agent 独立运行 → 规则评分 → 辅助 judge → 人工抽检与分歧复核 → 对照报告。
- **验收出口**：原始记录独立，条件差异和不可比维度公开；定位、恢复、误操作、成本和人工介入分别比较。judge 不替代确定性断言或真实健康，样本与人工校准细则在运行前固定。
- **证据**：各方案配置和版本、同条件说明、逐次结果、评分和抽检原文、失败及费用。
- **范围边界**：不能把模型差异冒充架构收益，不预设本项目获胜；小样本和单机结论不推广为生产准确率。

### MS20：第三方复现与使用交付

- **新增能力**：未参与实现的使用者可按文档部署、运行、审批和追问，复现已报告的能力与限制。
- **前置依赖**：MS09–MS19 的完整目标能力及版本化证据。
- **完整操作链**：干净实验资源准备 → 锁定版本安装／部署 → 按 CLI 或 CLI skill 触发 → 调查／审批／验证 → 回查报告 → 清理。
- **验收出口**：部署、演示和 CLI skill 使用说明与实际版本相符，命令真实验证，无作者临时路径或旧配置依赖；第三方复现记录包含失败和修订。只读代码回归、回放与真实集群验收清楚区分。
- **证据**：安装与复现日志、环境差异、完整导出包、操作截图、版本清单和清理结果。
- **范围边界**：本机实验交付不等于生产部署、高可用或企业权限治理；产品多 Agent 仍是基于 eval 的后续增量，开发并行不算产品能力。
