# 演示

两周展示目标为 MS01：健康业务基线 → 实验坏发布与核验 → 真实告警和最小 webhook → 假设调查与证据 → 提案及规则／人工授权 → 受控回退 → 真实业务健康验证 → CLI、静态报告与完整证据包 → 环境复位。

2026-11-04 完成第一次端到端运行，报告与证据在 [`ms01/`](ms01/README.md)：事件、调查、提案、审批、执行和恢复都有数据库记录与截图，八个步骤全部走到。第 5 步的提案由操作者发起，模型结论没有自动转成提案，报告第 6 节列出了全部缺口。

这里没有一键演示脚本。报告记录的是实际执行过的命令与观察；逐步复现按报告第 8 节执行，复位按第 9 节确认。同日补充运行已经接通模型提案，见报告第 7 节。

MS02 的审批跨进程证据在 [`ms02/`](ms02/README.md)：提案等待、进程退出、重启查询、批准／拒绝、过期失效与单次执行都有命令记录和集群观测。

MS03 的持续 OOM 证据在 [`ms03/`](ms03/README.md)：降低内存限额后的持续 OOMKilled、业务受损、调查定位到规格回归、重建不适用判断、回退历史模板并验证恢复；同时记录告警自动调查未完成结论的缺口。

I01 的环境与坏发布实验证据在 [env](../env/README.md) 和 [`faults/f01-bad-release/`](../faults/f01-bad-release/README.md)，它们是实验关卡，不含告警入口、模型调查、提案、授权和 CLI 报告。具体步骤与断言以 [MVP 展示链路](../docs/mvp.md#4-两周展示链路)为准。

调查不足、动作不适用、拒绝或恢复失败时保留真实状态；Kubernetes 自恢复、操作者修复与清理工具复位不能冒充 Agent 恢复。展示时只宣称证据支持的阶段，不把 MS01 称为完整 MVP。
