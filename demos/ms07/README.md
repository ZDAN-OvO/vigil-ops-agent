# MS07 证据：调查结果只读追问

2026-11-05 首次执行。操作者可以对已完成的调查提问，回答只能引用已有证据，缺信息就明说，不新增查询也不执行动作。

## 实现

`aiops explain <调查 ID> "<问题>"` 读取调查、事件、假设和证据，把记录交给模型，要求：

- 只使用记录里的事实，引用时写 evidence id。
- 引用了记录里不存在的 id 会被拒绝，命令退出非零，审计写 `explain.rejected`。
- 记录不足时在 `missing` 里写缺什么，`needs_new_query` 置为 true。
- 没有工具可用，也没有写操作；服务只读存储并追加两条审计。

## 实机运行

调查 `inv-2facf6216bc0`（MS06 的错误 Context 反例，10 条证据、12 次工具调用）上做了两次追问。

**有据可答。** 问「为什么判断是内存限额不足，而不是节点磁盘写满？」回答分四点：OOMKilled/137 与 16Mi 限额、事件里没有 Evicted 与 DiskPressure、frontend 日志的连接被拒、以及证据边界（Prometheus 不可用，磁盘指标没取到）。引用 5 条证据，`needs_new_query=false`。

**缺证据。** 问「上次发布是谁批准的？」回答明确说记录里只有 revision 与 change-cause，没有审批人字段，并在 `missing` 里列出需要审批记录、变更单和操作主体，`needs_new_query=true`。引用只落在确实存在的证据上。

**只读核对。** 两次追问前后：状态 `completed`、结论哈希 `1213502e…`、证据 10 条、工具调用 12 次、提案 1 条、执行记录 0 条，全部不变。追问只新增 `explain.requested`、`explain.answered`，以及一条 `explain.rejected`。那条 rejected 来自开发中的过严规则：它把「有引用但附带边界说明」的回答当成自相矛盾拒掉了，规则修正后重问通过；记录保留。调查本身的审计行没有变化。

## 缺口

- 引用只校验 id 是否存在于本调查，不校验回答内容是否真的被该证据支持；有引用时允许附带边界说明，不要求 `needs_new_query`。
- 没有回答质量评分，也没有对「需要新查询」的后续动作；续查要操作者另外发起调查。
- 模型自报的理由没有交叉核对，与 MS06 的 runbook 理由同样只是记录。
- 只接受 `completed` 的调查；`running`、`inconclusive` 等状态直接拒绝，这条由测试覆盖，实机只跑过已完成的那条。
- 只读保证来自「没有工具、没有写路径」的代码结构与前后计数，不是运行时权限隔离。
