三处需要单独说明：

1. **通用 Agent 臂在评审修复后重跑过。** 第一版实现把委派能力一起移除了（与"只去掉
   Skill 与提示词"不符），修复后重跑 3 次；修复前的 3 次不计入本记录。这条臂现在与
   另外两条一样有委派调查，只是子调查不加载 Skill。
2. **判定口径经过六轮收紧。** 正式结论优先于假设（不再拼接）；带否定词的片段不计命中；
   证据检查要求原始指标表达式、读取真实取值、并指向本场景的探针 job（`job="frontend-probe"`），
   `1 - probe_success` 这类派生表达式和别的 job 的异常都不算；结论关键词必须落在同一个
   肯定片段里（"Redis 正常，延迟来自 CPU 饱和"不给分，记待复核）；证据不取被反驳假设的
   关系；成本与人工介入纳入比较；任一条臂有样本缺耗时时该维度记不可比；期望动作之外的
   处置记越界。越到后面越保守：异常的采样值必须出现在目标 job 那条序列上（目标探针正常、
   旁边备份 job 掉了不算）；成本"没记录"与"真的 0 次"分开（某臂超时、没留调查 ID 时成本
   记未知，不当零成本）。重算后通用 Agent 的 2 次恢复没有转成"诊断正确"：其中一次结论漏了判据、
   一次没抓到 5xx 日志；另有 1 次既没形成结论也没提动作。这不是判定错误——它确实没有
   把证据整理成可复核的诊断，只是失败在不同环节上。
3. **3 次被替换的通用 Agent 运行留在记录里。** 第一版实现误删了委派能力，与臂定义
