# 故障目录（待实现）

完整目标为资源、依赖、配置发布、网络四类共 12 个可复现场景，每个场景提供 `inject/verify/cleanup`。本目录尚无注入脚本，机制和验收以 [MVP 场景卡](../docs/mvp.md#5-场景卡)为准。

首个切片为 F01 坏发布：实验镜像能启动但关键业务请求失败，经调查和受控回退验证真实业务恢复。F02 为持续内存限额不足的 OOM，必须正确判断 Pod 重建无法改变故障规格。F03 为实验代理保持的 Redis 访问链路延迟，不称为 Redis 内部阻塞；现有动作不适用时停止。

A01 是专用无状态工作负载的独立 Pod 重建验证用例，不拼入核心三场景分母。临时故障必须经实验证明跨容器重启持续、Pod 重建消除，不能把 Kubernetes 自恢复算成 Agent 成功。

其余 12 场景覆盖项逐步核对真实业务能力，不将同一故障换名凑数。“回退上一版”是动作，不是故障类型；Redis 不应被假定有应用连接池，磁盘注入需要隔离卷。

注入器可以在专用环境制造故障，不意味着 Agent 获得任意配置修改权限。场景真值、脚本和命名不进入调查模型可读范围。`cleanup` 属于结果判定后的环境复位，记录 actor、时间和健康状态，不计 Agent 修复成功。
